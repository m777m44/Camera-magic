# تغيير الاسم فقط وبناء ونشر APK

## الحالة الحالية — اقرأ أولًا

لا توجد في المستودع نسخة Blackmagic Camera الأصلية، ولا APK نهائي منشور، ولا مفتاح
توقيع إنتاجي. `hdr-kit` مكتبة وليست تطبيق Blackmagic. لا يمكن تحويلها إلى التطبيق
الأصلي أو اختلاق واجهته بمجرد تغيير نوع موديول Gradle إلى application.

هذا المسار يجهّز البناء والنشر **عند توفير المدخلات**. لا ينشر تطبيقًا بديلًا أو
حزمة الاختبارات باسم Blackmagic. النشر متوقف افتراضيًا، والرابط المستقبلي يعيد 404
قبل وجود أول إصدار منشور يحتوي على الملف. التفعيل لا يولّد الأصل أو المفتاح تلقائيًا.

## ماذا يعني «نفس الأصل مع تغيير الاسم»؟

`rename-apk` مستقل عن `patch/build/sign` التجريبي الأقدم:

| العنصر | وضع الاسم فقط |
|---|---|
| اسم التطبيق وقاذفات Launcher | `Blackmagic Camera Mahdi` |
| الباكج / الأصناف / providers / الأذونات | يحتفظ بالأصل |
| الأيقونة وواجهة التطبيق الموجودة | لا يضيف أيقونة أو واجهة جديدة |
| minSdk / targetSdk / versionCode / versionName | يحتفظ بالأصل، لا يخفض أو يرفع SDK |
| DEX | يحفظ البايتات الأصلية باستخدام `apktool d --no-src` |
| مكتبات native وassets | يقارن SHA-256 لكل ملف قبل اعتماد الناتج |
| الفلاتر | لا يضيف LUTs أو مكتبة HDR أو أزرارًا جديدة |
| التوقيع | **جديد بالضرورة** بعد تعديل الحزمة |

يُغيَّر مرجع label للتطبيق والقاذفات إلى مورد نصي جديد، دون تعديل النصوص المحلية
أو شاشات التطبيق أو الأصناف. تتغير أيضًا بيانات الموارد الثنائية والتغليف عند
إعادة البناء. لذلك ليست الحزمة مطابقة للأصل byte-for-byte، ولا تحمل شهادة الناشر.

حتى مع ثبات DEX والمكتبات قد يعتمد التطبيق على شهادة الناشر أو فحوص سلامة أو خدمات
خارجية. لا يتجاوز المسار هذه الفحوص ولا يضمن بقاء كل الوظائف. يلزم اختبار الكاميرا
والتسجيل على النسخة الفعلية بعد توفيرها؛ اختبارات هذا المستودع ليست اختبارات Blackmagic.

### التثبيت والتحديثات

لأن الباكج الأصلي باقٍ والتوقيع جديد، لا يمكن تثبيت الناتج فوق التطبيق الرسمي ذي
الشهادة المختلفة. قد تحتاج إزالة الرسمي أولًا بعد نسخ بياناتك؛ الإزالة قد تمسحها.
ولا يمكن تثبيت النسختين جنبًا إلى جنب دون تغيير الباكج، وهو تغيير خارج وضع «الاسم فقط».
لا نطلب تعطيل حماية الجهاز. يبقى نطاق Android والعتاد كما يفرضه الأصل.

استخدم **المفتاح الإنتاجي نفسه** لكل تحديث. لا تنشئ مفتاحًا جديدًا كل مرة. ضياعه أو
تغييره يمنع التحديث العادي فوق نسختك السابقة. إبقاء versionCode كما في الأصل مقصود؛
رقم إصدار GitHub يتغير، لكن لا نزعم وجود versionCode متزايد أو محدث تلقائي داخل التطبيق.

## بناء محلي بعد توفير الأصل

المطلوب: Python 3.11+، JDK/Java وkeytool، Apktool 2.11.1+، وSDK Build-Tools 35+.
النشر يستخدم JDK 21 وBuild-Tools 36.0.0 المحدد صراحةً في
`config/release-toolchain.json` وApktool مثبتًا بمجموع تحقق في
`config/release-tools.json`. يستخدم اختبار دورة البناء الإعداد نفسه، ولا يختار إصدار
SDK أعلى لمجرد وجوده على runner. تُنسخ aapt2 إلى مجلد عمل مؤقت مملوك للمستخدم لأن
Apktool يغيّر إذن التنفيذ؛ لا نغيّر أذونات SDK المثبتة على النظام.
لا تتضمن المصادر أدوات ثنائية أو APK مملوكًا لطرف ثالث.

1. ضع APK أصليًا مستقلًا، حصلت عليه بصورة مشروعة، في `inputs/original.apk`.
2. تحقق من مصدره وشهادة توقيعه مقارنةً ببصمة الناشر الموثوقة حيث تتوفر. SHA-256
   يثبت ثبات ملف معين، وليس أنه أصلي أو آمن أو مرخص لإعادة النشر.
3. هيئ الأدوات كما في [TOOLCHAIN.md](TOOLCHAIN.md).
4. أنشئ مفتاحك مرة واحدة محليًا أو استعمل مفتاحك السابق. لا ترسل كلمات المرور أو
   المفتاح في المحادثة أو في Git. مثال طرفية محلية:

```bash
source .venv/bin/activate
read -r -s -p 'Keystore password (12+ characters): ' MAHDI_STORE_PASSWORD; echo
export MAHDI_STORE_PASSWORD
export MAHDI_KEY_PASSWORD="$MAHDI_STORE_PASSWORD"
# تجاوز keygen إن كان المفتاح موجودًا؛ لا تستبدله.
python -m camera_magic keygen --keystore keys/mahdi-release.jks --alias mahdi
python -m camera_magic rename-apk inputs/original.apk \
  --keystore keys/mahdi-release.jks --alias mahdi \
  --output artifacts/Blackmagic_Camera_Mahdi.apk
unset MAHDI_STORE_PASSWORD MAHDI_KEY_PASSWORD
```

لا يستبدل الأمر الأصل أو ملف إخراج موجودًا. يحفظ الناتج فقط بعد التوقيع والتحقق
ومقارنة الهوية وSDK والإصدار والأذونات وDEX والمكتبات والـassets. فحص التوقيع يمتد
إلى v1/v2/v3، ويستخدم نطاقًا تشفيريًا يبدأ بـAPI 23 دون تغيير minSdk الفعلي في Manifest.
تأتي الملفات الناتجة في `artifacts/`، ومعها `.verification.json`. تبقى مخرجات البناء
والأصل والمفتاح خارج Git. لا يقبل المسار Split APK ناقصًا أو sharedUserId يحتاج مراجعة.

## إعداد النشر التلقائي مرة واحدة

**المستودع عام. فعّل النشر فقط إن كنت مخولًا بإعادة توزيع الأصل والنسخة المشتقة.**
الاستخدام التعليمي/الشخصي أو عبارة حفظ الحقوق لا يمنحان وحدهما إذن إعادة التوزيع.
ترخيص MIT هنا للأدوات الأصلية فقط ولا يعيد ترخيص Blackmagic Camera أو علاماته.

من إعدادات المستودع: Settings → Secrets and variables → Actions. لا تضع القيم
السرية داخل ملفات YAML أو أوامر مكشوفة أو هذه المحادثة.

### Repository secrets

| الاسم | القيمة التي يحتفظ بها المالك |
|---|---|
| `APK_SOURCE_URL` | رابط HTTPS مباشر إلى APK مستقل مشروع ومسموح بإعادة توزيعه؛ يمكن أن يكون رابطًا خاصًا طويل الصلاحية. لا تضع user:password داخل الرابط. |
| `APK_KEYSTORE_B64` | ترميز base64 في سطر واحد لمفتاحك الإنتاجي الثابت، وليس مفتاح CI التجريبي. |
| `APK_KEYSTORE_PASSWORD` | كلمة مرور مخزن المفتاح، 12 حرفًا على الأقل. |
| `APK_KEY_PASSWORD` | كلمة مرور المفتاح الخاص، 12 حرفًا على الأقل؛ قد تساوي الأولى وفق إعدادك. |

على Linux يمكن رفع المفتاح إلى Secrets عبر gh دون طباعته:

```bash
base64 -w0 keys/mahdi-release.jks | gh secret set APK_KEYSTORE_B64 --repo m777m44/Camera-magic
```

استخدم واجهة الإعدادات أو إدخال gh الآمن لبقية القيم، ولا تكتب كلمات المرور كقيم
`--body` في أوامر تُحفظ في السجل. احفظ نسخة احتياطية خاصة للمفتاح خارج CI.

### Repository variables (ليست أسرارًا)

| الاسم | القيمة |
|---|---|
| `APK_SOURCE_SHA256` | SHA-256 الكامل، 64 خانة، للأصل الذي وثقت به. احسبه بـ`sha256sum inputs/original.apk`. |
| `APK_KEY_ALIAS` | `mahdi` أو alias الفعلي داخل المخزن. |
| `APK_RELEASE_ENABLED` | لا تضبطه إلى `true` إلا بعد إعداد المصدر والمفتاح وامتلاك حق النشر؛ تركه غير موجود يبقي النشر متوقفًا. |

لا يجري تنزيل عشوائي من Play/APKMirror، ولا يُخزَّن الأصل في Git أو كأصل إصدار عام.
إن كان الرابط مؤقتًا أو تغير محتوى المصدر فلن يكفي SHA قديم؛ يفشل البناء آمنًا ويبقى
آخر إصدار ناجح. لتحديث أصل التطبيق: حدّث الرابط والبصمة بعد التحقق من النسخة الجديدة،
ثم شغّل التحقق على main من واجهة Actions أو ادفع تحديثًا معتمدًا.

## كيف يحدث النشر بعد كل تحديث؟

1. يدمج التحديث في `main`، فتعمل `Source and HDR kit validation`.
2. لا يبدأ النشر التلقائي إلا بعد نجاحها، وعلى `main` ومن المستودع نفسه، ومع تفعيل
   المتغير أعلاه. لا يوجد `pull_request_target` أو تحميل حزم من PR غير موثوق.
3. يُحمَّل المصدر وApktool عبر HTTPS مع تثبيت SHA-256. لا تُطبع عناوين المصدر السرية.
4. يُستعاد المفتاح الثابت بصلاحيات 600 على runner مؤقت؛ لا يُنشأ مفتاح إنتاجي متغير.
5. يبني `rename-apk` النسخة، ويوقعها، ويتحقق من ثبات ملفاتها ومعلوماتها.
6. يُنشأ إصدار برقم بناء مستقل، وتُرفع إليه الأصول وهو **Draft**:
   - `Blackmagic_Camera_Mahdi.apk`
   - `Blackmagic_Camera_Mahdi.verification.json`
   - `SHA256SUMS.txt`
7. بعد اكتمال الرفع ومراجعة SHA الحالي لـmain يُنشر الإصدار ويُعلَّم Latest. لا
   يُحذف APK الإصدار السابق ولا يُستبدل ملفه في مكانه. البناء الأقدم من main لا ينشر
   نفسه كأحدث؛ وقد تبقى مسودة غير منشورة إذا تقدم main أثناء الرفع.
8. يُحذف الأصل المؤقت والمفتاح من runner حتى عند الفشل.

التشغيل اليدوي من واجهة Actions ممكن على main بعد الإعداد؛ واجهة GitHub أو الاتصال
المستخدم تحتاج صلاحية Actions المناسبة. لا حاجة لإرسال رموز دخول GitHub في المحادثة.

تعديلات مكتبة HDR المستقلة لا تدخل في APK الاسم فقط. وكذلك لا تُجلب إصدارات جديدة
من الناشر تلقائيًا دون تحديث المصدر والبصمة. لا يوجد محدث ذاتي داخل التطبيق؛ المطلوب
هنا رابط تنزيل ثابت لآخر بناء ناجح، وليس تثبيت تحديثات تلقائيًا على الهاتف.

## رابط التنزيل الثابت

**لا يوجد APK خلف هذا العنوان بعد؛ يبدأ العمل بعد أول نشر مكتمل فقط:**

```text
https://github.com/m777m44/Camera-magic/releases/latest/download/Blackmagic_Camera_Mahdi.apk
```

يبقى اسم الأصل ثابتًا، ويحوّل GitHub الطلب إلى نفس الاسم في الإصدار المعلّم Latest.
التحديث الفاشل لا يستبدل آخر بناء ناجح. قد يوجد تخزين مؤقت قصير في المتصفح/CDN.
حافظ على اسم الأصل في كل إصدار، ولا تعلّم إصدارًا يدويًا خاليًا من APK على أنه Latest؛
الرابط لا يمكنه تعويض حذف الإصدارات أو تغيير الاسم أو غياب أول بناء.

## ما الذي اختبرناه وما الذي لم نختبره؟

- اختبارات الوحدة تغطي وضع الاسم فقط، والهوية/SDK/الإصدار، وثبات DEX/native/assets،
  وحماية الأسرار، وتثبيت SHA، وحدود التنزيل، وشروط النشر ومسودة الإصدار.
- CI يبني APK الاختبارات الخاص **بهذا المشروع** ثم ينفذ عليه دورة Apktool حقيقية
  لتغيير الاسم والمحاذاة والتوقيع والتحقق. الناتج يسمى `fixture-renamed.apk` باسم
  عرض تجريبي مميز، ولا يُنشر كنسخة Blackmagic أو أصل تنزيل للمستخدم.
- مصفوفة API 23/29/33/35 تختبر مكتبة GL الأصلية فقط، كما يشرح [TESTING.md](TESTING.md).
- لم تُقدّم APK Blackmagic، لذلك لم تُعد تسميتها أو تُوقّع أو تُرفع أو تُختبر وظائفها.
  لا يساوي نجاح هذه الاختبارات تحقيق توافق التطبيق الأصلي مع كل الأجهزة.
