# Mahdi Camera · Camera-magic

**تطبيق كاميرا Android مستقل ومفتوح المصدر**، وليس Blackmagic Camera ولا نسخة معاد
تسميتها منه. اختار صاحب المشروع صراحةً بناء تطبيق مستقل بدل تعديل تطبيق Blackmagic.
كود التطبيق وواجهته وأيقونته أصلية هنا؛ لا تُضمّن حزمًا أو رسومات أو خدمات Blackmagic.

## تنزيل APK

اسم الملف الثابت للإصدارات الناجحة هو **`Mahdi_Camera.apk`**:

```text
https://github.com/m777m44/Camera-magic/releases/latest/download/Mahdi_Camera.apk
```

[صفحة الإصدارات](https://github.com/m777m44/Camera-magic/releases) تحتوي APK وتقرير
التحقق و`SHA256SUMS.txt` بعد اكتمال أول نشر. وجود هذا الرابط في المصدر ليس وحده دليلًا
على نجاح نشر؛ راجع أصول الإصدار الفعلية. البناء أو التوقيع الفاشل لا يستبدل آخر APK ناجح.
الرابط القديم `Blackmagic_Camera_Mahdi.apk` يخص المسار السابق، وليس هذا التطبيق المستقل.

## الوظائف المنفذة

- معاينة حية بـCamera2، واختيار الكاميرات والدقات التي يعلنها الجهاز، حتى 1080p.
- تسجيل فيديو **H.264 داخل MP4**، مع **AAC** من الميكروفون أو تسجيل صامت.
- حفظ التسجيلات في **`DCIM/MahdiCamera`** وتشغيل آخر مقطع عبر مشغل الفيديو الموجود بالجهاز.
- ISO وسرعة الغالق يدويًا عند وجود `MANUAL_SENSOR`، وتركيز يدوي عند دعم العدسة.
- إعدادات توازن الأبيض التي يدعمها الجهاز، وتعويض التعريض التلقائي وzoom رقمي.
- شبكة أثلاث وعلامة مركز للمعاينة فقط، وعدّاد مدة التسجيل؛ ليست مؤثرات تُطبع على الفيديو.
- واجهة داكنة أصلية تتكيف مع الوضعين العمودي والأفقي. يثبت الاتجاه أثناء التسجيل.
- إيقاف التسجيل وإغلاق الكاميرا عند مغادرة الواجهة؛ لا يوجد تصوير خلفي أو خدمة خفية.

التحكم غير المدعوم يكون معطلًا وباهتًا؛ لا نعرض أزرارًا وهمية لميزات غير منفذة.
معدل الإطارات مستهدف حول 30 حسب نطاق الكاميرا، وليس ضمان جودة أو أداء على كل جهاز.
المعرّف **`com.mahdi.camera`** مستقل عن تطبيق Blackmagic، فلا يحتاج إزالة التطبيق الرسمي.

## الخصوصية والأذونات

لا يوجد إذن **INTERNET**، ولا حساب أو إعلانات أو تتبع أو رفع سحابي.
أذونات الكاميرا والميكروفون يطلبها Android أثناء التشغيل. يمكن إطفاء الميكروفون؛
رفضه لا يمنع التسجيل الصامت. على Android 6–9 فقط يُطلب إذن حفظ الملفات العامة؛
من Android 10 يستعمل التطبيق MediaStore وملفًا معلقًا حتى نجاح إغلاق التسجيل.
تُحذف المخرجات الفاشلة/القصيرة جدًا قدر الإمكان بدل عرضها كمقاطع ناجحة.

## الحدود المهمة

- الحد الأدنى API 23 / Android 6؛ target/compile API 35.
- لا توجد وعود بتوافق جميع عدسات وأجهزة Samsung/Xiaomi/Huawei أو جودتها.
- **لا يتضمن هذا الإصدار HDR حقيقيًا أو pseudo-HDR أو LUT processing أو ProRes أو
  Blackmagic Cloud أو التزامًا بمطابقة جميع ميزات Blackmagic.**
- `hdr-kit` وLUTs الموجودة من المرحلة السابقة مكتبة مرجعية منفصلة، **غير مربوطة
  بهذا التطبيق**؛ نجاح اختبارات شيدراتها لا يثبت تسجيل فلاتر داخل Mahdi Camera.
- يلزم اختبار ميداني للألوان، الصوت، اتجاه الصورة، الحرارة، التسجيل الطويل، مساحة
  التخزين والعدسات على هواتف حقيقية قبل الاعتماد عليه في تصوير مهم.
- الإصدار الحالي للتجربة والاستخدام الشخصي؛ لم يُنشر في متجر Play.

## البناء والاختبار

المطلوب JDK 17+ (CI يستخدم 21)، Gradle **8.11.1**، Android SDK API 35
وBuild-Tools **36.0.0**. لا تحتاج APK من Google أو Apktool لبناء التطبيق المستقل.

```bash
sdkmanager "platforms;android-35" "build-tools;36.0.0"
export MAHDI_VERSION_CODE=$(git rev-list --count HEAD)
gradle :camera-app:assembleDebug :camera-app:testDebugUnitTest :camera-app:lintDebug
# بناء release غير موقع؛ لا يُقدّم كـAPK نهائي قابل للتثبيت قبل التوقيع والتحقق.
gradle :camera-app:assembleRelease
```

اختبارات التطبيق الفعلية في `.github/workflows/camera-app.yml` تبني وتفحص Lint،
ثم تفتح كاميرا المحاكي على API 23 و35، وتسجل MP4 وتتحقق من عينات H.264 وAAC،
وفك إطار فيديو، وحفظ المقطع واستعادة المعاينة، وإغلاق/إعادة فتح الكاميرا عند الخلفية.
تُحفظ لقطة المحاكي والمقطع التجريبي في CI artifacts؛ ليست لقطات هاتف حقيقي أو صورًا مولّدة.
نتائج التنفيذ تؤخذ من حالة CI الفعلية، وليس من وجود ملف الاختبار فقط.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m unittest discover -v
python scripts/check_java_syntax.py
```

للتثبيت المحلي التجريبي بعد توصيل جهازك المصرح به:

```bash
adb -s SERIAL install -r camera-app/build/outputs/apk/debug/camera-app-debug.apk
```

نسخة debug تختلف بشهادة التوقيع عن release. لا تفترض تحديث إحداهما فوق الأخرى.
التحديثات المنشورة تحتاج **نفس المفتاح الخاص** وبصمته العامة في
`config/mahdi-camera-signing.json`. لا توجد مفاتيح خاصة في Git أو أصول الإصدارات.

## النشر والتحديثات

[دليل النشر والتوقيع](docs/APP_PUBLISHING.md) يشرح المفتاح الثابت، Secrets، وتسليم
APK الموقعة محليًا إلى CI دون كشف المفتاح. ينتظر الناشر اختبارات التطبيق الناجحة
على **main الحالي نفسه**، ويعيد البناء ويقارن محتوى APK قبل إتاحة التنزيل.
إذا لم تُهيأ Secrets، لا يولد CI مفتاحًا جديدًا كل مرة ولا ينشر توقيعًا متغيرًا؛
يمكن للمالك توقيع APK محليًا بالمفتاح الثابت ثم إرسال **الحزمة العامة فقط** للتحقق والنشر.

## خريطة المستودع

```text
camera-app/          التطبيق المستقل + اختبارات وحدة واختبارات تسجيل على Android
camera_magic/        مساعدات البناء/النشر وأدوات APK القديمة
config/              إعدادات الأدوات وبصمة الشهادة العامة فقط
hdr-kit/             مكتبة GL مرجعية منفصلة (ليست مدمجة بالتطبيق)
assets/mahdi_hdr/     LUTs وشيدرات المرحلة السابقة (ليست مدمجة بالتطبيق)
docs/                أدلة وحدود واختبار ونشر
.github/workflows/   تحقق التطبيق/المكتبة ونشر APK خارج Git
```

أدوات إعادة التسمية السابقة محفوظة ولم تُحذف، لكنها ليست طريقة بناء التطبيق الحالي:
[أرشيف دليل الأدوات](docs/LEGACY_TOOLKIT.md)، [نشر نسخة اسم فقط](docs/PUBLISHING.md)،
[التكامل المرجعي GL](docs/INTEGRATION.md). لا تفعّل ناشر النسخة القديمة بالتوازي مع
ناشر Mahdi Camera كي لا تشير Latest إلى إصدار لا يحتوي اسم الملف المطلوب.
